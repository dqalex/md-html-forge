# Theme API

A theme = a group of CSS variable overrides + segment-level background styling.
The same component renders differently under different themes but the HTML
structure is identical.

## Two scopes where a theme applies

Forge threads themes through **two** CSS scopes. Keep both in mind.

| Scope | Where | What it does |
|---|---|---|
| `:root + body` | Generated by `buildRootThemeCss(theme)` | Global page chrome — affects body background, default font, the shared `--ivory / --gray-* / --slate / --clay` tokens for the **whole page** |
| `.theme-<id>` | Generated by `buildThemeCss(theme, bandStyle)` | Segment-level — wraps one `@theme <id>` segment with its own background + overrides, so you can drop a dark banner inside an ivory page |

The root theme is **the first `@theme` in the document** (so the toolbar's
"global theme" dropdown = upserts that first `@theme`). Subsequent segment-level
`@theme` directives override root-scope variables within their section only.

## ThemeDef

```ts
interface ThemeDef {
  id: string;            // 'editorial' | 'dark' | 'mono' | custom slug
  name: string;          // display label

  // ==================== Colors ====================
  background?: string;   // --ivory        page / segment base
  text?: string;         // --gray-700     body copy
  heading?: string;      // --slate        headings
  strong?: string;       // --slate        bold emphasis
  accent?: string;       // --clay         links, markers, chips
  accentSoft?: string;   // --oat          soft accent surface
  muted?: string;        // --gray-500     secondary text, captions
  success?: string;      // --olive
  warning?: string;      // --rust

  surface?: string;      // --white        card / panel background
  // Second-tier surface — used by code chunks, inline code, input fields,
  // striped rows. In dark themes you MUST set this, otherwise cards end up
  // with beige blobs inside them.
  surfaceSunken?: string; // --gray-100

  border?: string;       // card / panel border (full border shorthand)
  // Subtle divider — used for row separators, dashed boxes, disabled borders.
  // In dark themes you MUST set this, otherwise dividers look harsh.
  borderSubtle?: string; // --gray-300

  radius?: string;       // --radius-panel

  // ==================== Typography ====================
  fontSerif?: string;    // --serif   (titles, large metric values)
  fontSans?: string;     // --sans    (body)
  fontMono?: string;     // --mono    (code, data)

  // ==================== Segment geometry ====================
  bandStyle?: 'contained' | 'full-bleed';
  // 'contained' (default): segment background respects .page width
  // 'full-bleed'         : segment background bleeds to viewport edges;
  //                        content still aligns to .page width

  sectionGap?: string;   // CSS margin shorthand between segments (default '24px 0')
  sectionInset?: string; // CSS padding inside a segment       (default '28px 32px')

  // ==================== Escape hatch ====================
  extraCss?: string;     // raw CSS, scoped under .theme-<id>
}
```

## CSS variable mapping

Forge historically names its tokens after the editorial palette (`--ivory`,
`--clay`, `--slate`, `--gray-*`). Themes override those names — component CSS
never needs to know which theme is active.

| ThemeDef field | CSS var | Typical usage in components |
|---|---|---|
| `background` | `--ivory` | page/segment base |
| `text` | `--gray-700` | `color: var(--gray-700)` for body |
| `heading` / `strong` | `--slate` | headings, `<strong>` |
| `accent` | `--clay` | links, chips, active states |
| `accentSoft` | `--oat` | soft highlight backgrounds |
| `muted` | `--gray-500` | captions |
| `surface` | `--white` | cards |
| `surfaceSunken` | `--gray-100` | code backgrounds, inline `<code>`, striped rows |
| `border` | `--border` (shorthand) | card borders |
| `borderSubtle` | `--gray-300` | dividers, dashed frames |
| `radius` | `--radius-panel` | card corners |
| `fontSerif` / `fontSans` / `fontMono` | `--serif` / `--sans` / `--mono` | type stacks |

## How segments get wrapped

```md
<!-- @theme dark -->

# heading inside dark segment
```

Emitter produces:

```html
<section class="theme-section theme-dark">
  <!-- all components in this segment -->
</section>
```

And the generated CSS looks like:

```css
/* Root-scope, applied to the whole document (first @theme in doc) */
:root { --ivory: #141413; --gray-100: #28282A; --clay: #D97757; /* ... */ }
body { background: #141413; color: #E3DACC; }

/* Segment-scope, applied only to .theme-dark sections */
.theme-dark { --ivory: #141413; --gray-100: #28282A; /* ... */ }
.theme-dark { background: #141413; color: #E3DACC; padding: 36px 36px; margin: 32px 0; border-radius: var(--radius-panel, 12px); }
```

## Built-in themes (`src/builtin/themes/preset-themes.ts`)

| id | feel | accent | use |
|---|---|---|---|
| `editorial` | ivory + serif + clay | `#D97757` | default; articles / reports |
| `dark` | deep slate + oat accent | `#D97757` | hero banners, code-heavy pages |
| `mono` | b/w print | `#000000` | minimal / publication |
| `sage` | olive on ivory | `#788C5D` | backward-compat |
| `cobalt` | blue-forward | `#0056FF` | backward-compat |
| `sunset` | coral warm | `#D97757` | backward-compat |

Only `editorial / dark / mono` appear in the toolbar picker; the rest are kept
registered for backward compat with older documents.

## Registering a custom theme

```ts
import { forgeRegistry } from '@/builtin';

forgeRegistry.registerTheme({
  id: 'neon',
  name: 'Neon Cyber',
  background: '#0a0a0a',
  text: '#e0e0e0',
  heading: '#ffffff',
  accent: '#00ff88',
  accentSoft: '#00ff8820',
  surface: '#1a1a1a',
  surfaceSunken: '#141414',
  border: '1px solid #2a2a2a',
  borderSubtle: 'rgba(255,255,255,0.08)',
  fontMono: '"JetBrains Mono", ui-monospace, monospace',
  extraCss: `
    .comp-feature-card { box-shadow: 0 0 20px rgba(0, 255, 136, 0.2); }
  `,
});
```

Available immediately via `<!-- @theme neon -->`. You can also persist user
themes to `localStorage` through the Brand Pack UI (`ThemeEditorModal`).

## Design guidelines

### Contrast

- `text` / `background` contrast ≥ 4.5 (WCAG AA)
- `accent` / `background` contrast ≥ 3.0

### Don't break layout

Theme CSS should change **color / font / shadow only**. Avoid:

- `position`, `transform`, `display: none`
- `width`, `height`, `padding`, `margin` on anything other than the theme
  section itself (where `sectionGap` / `sectionInset` is the sanctioned lever)

If a theme needs to hide a decorative element, toggle `opacity` via a
theme-scoped CSS variable rather than removing it.

### Dark themes must set `surfaceSunken` and `borderSubtle`

This is the pit every dark theme falls into once. Components across the library
use `background: var(--gray-100)` for code chunks and `border: ... var(--gray-300)`
for dividers. Without overrides these stay at their ivory-palette defaults and
you get beige blobs + harsh pale lines on a dark background.

All built-in dark-ish themes and all dark-mood presets in `ThemeEditorModal`
already set both. Custom themes you author should too.

### Prefer variables, not selector overrides

```css
/* Good — component uses the token, theme overrides the token. */
.theme-dark { --clay: #5EEAD4; }
.comp-callout { border-left-color: var(--clay); }

/* Avoid — ties theme to specific component selectors. */
.theme-dark .comp-callout { border-left-color: #5EEAD4; }
```

### `bandStyle` selection

- `contained` (default) — visually coherent with surrounding segments
- `full-bleed` — banner/hero only; use sparingly for strong contrast moments
